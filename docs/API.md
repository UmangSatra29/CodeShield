# API and data model

Base URL: `http://localhost:4000/api`. Authenticate with `Authorization: Bearer <JWT>`. JWTs contain account role; handlers enforce role and ownership.

## Key endpoints

| Method | Path | Role | Purpose |
|---|---|---|---|
| POST | `/auth/register`, `/auth/login` | Public | Password-hashed accounts and JWT session |
| GET | `/me` | Signed in | Current account |
| GET / POST | `/courses` | Signed in / teacher | List owned or joined classes; create a class with a generated join code |
| POST | `/courses/join` | Student | Join a class by its code |
| GET | `/assignments` | Student / teacher | Assigned published items for students; owned items for teachers |
| POST | `/assignments` | Teacher | Validates problem, attempts, tests, settings and 100% rubric |
| POST | `/assignments/:id/start` | Student | Creates/resumes attempt with a server deadline |
| GET | `/attempts/:id` | Owner / assignment teacher | Attempt state and authoritative deadline |
| PATCH | `/attempts/:id/code` | Student | Version-checked autosave |
| POST | `/attempts/:id/run` | Student | Visible test execution by private runner |
| POST | `/attempts/:id/events` | Student | Append proctoring and activity evidence |
| POST | `/attempts/:id/submit` | Student | Idempotent submission with attempt limit checks |
| GET | `/submissions/:id` | Owner / assignment teacher | Result and event evidence; hidden inputs stay private |
| POST | `/submissions/:id/suggest` | Teacher | Transparent rubric suggestion, not a final grade |
| POST | `/submissions/:id/review` | Teacher | Approve, override, request re-viva, or mark for review |
| POST | `/submissions/:id/viva/next` | Student | Code-specific adaptive viva scaffold |
| POST | `/viva/:id/answer` | Student | Store viva response and return follow-up |
| GET | `/assignments/:id/live`, `/analytics` | Teacher | Live sessions and assessment evidence |

Socket.IO accepts `session:join` and forwards `session:event` to monitor rooms. REST events are the durable audit path.

## Models

`User`, `StudentProfile`, `TeacherProfile`, `Course`, `Assignment`, `Question`, `TestCase` (assignment subdocument), `Attempt`, `Submission`, `CodeExecution`, `VivaSession`, `VivaQuestion`, `VivaAnswer`, `Rubric`, `RubricScore`, `ProctoringEvent`, `ActivityEvent`, `Feedback`, `TeacherReview`, and `Notification` are Mongoose schemas.

## Workflow and limits

- Attempt deadlines are generated by the API and survive client navigation. The client timer is informational; the server checks expiry.
- A unique idempotency key and attempt lookup prevent duplicate submissions.
- Student assignment responses remove hidden test cases. Run responses contain visible results only.
- Rubric suggestions attach score, maximum, evidence, and source. Viva points remain zero until viva evidence is integrated; teachers must approve or override before publishing.
- The viva assistant in `server/src/ai.ts` is a replaceable baseline question selector based on submitted code identifiers/control flow. It is not a hosted LLM integration.
- A class starts with no students and no assignments. Students join with the teacher-generated code; publishing an assignment to a class makes it visible to the class members.
- Face detection and camera streaming are not implemented. The exam panel marks face status as a demo placeholder. Browser fullscreen/tab sensors are planned UI surface and need durable client event integration before production.
